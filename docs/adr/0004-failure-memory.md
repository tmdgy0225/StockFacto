# ADR-0004: 실패 기록은 운영 런에만 쓰고, A/B 평가에서는 끈다

- 상태: 채택 (2026-10-13)

## 맥락
에이전트가 과거에 반복한 위반을 다음 실행에 미리 알려주면 첫 시도 성공률을 높일 수 있다(실패 기록 패턴).
그러나 기록이 평가 실행 사이에 누적되면 같은 케이스를 두 번 돌렸을 때 결과가 달라져 A/B 비교의 재현성이 깨진다.

## 결정
- 기록: 웹/API 로 실행한 하네스 런(`write=True`)의 위반만 `backend/runs/failures.json` 에 누적한다.
- 주입: API 런은 `use_memory=True` 로 상위 5개 규칙을 Plan 다음에 주입한다. 주입한 rule_id 는 `trace.plan.failure_memory` 에 남긴다.
- A/B 평가(`harness.eval`)와 테스트는 기록·주입 모두 하지 않는다.
- 개발 에이전트의 실수는 별도로 `docs/failures.md` 에 사람이 읽는 표로 관리한다.

## 결과
- 평가 재현성 유지.
- Mock 에이전트는 프롬프트를 읽지 않으므로 기억 주입의 효과는 Mock 으로 측정할 수 없다. 효과 측정은 Claude 실측(F-18)에서 `use_memory` 켜고/끄고 비교해야 한다.
